`InviteCodeStore.kt` 주석 정리했습니다.

## 지운 것 (코드를 그대로 옮겨 쓴 주석)

`// 초대 코드 저장소`, `// 캐시된 코드`, `// 초대 코드를 가져온다`, `// 캐시 확인`, `// API 호출`, `// 코드가 null 이면 null 반환`, `// 캐시에 저장`, `// 코드 반환`, `// 캐시를 비운다`, `// 캐시 데이터 클래스`, 그리고 `CachedCode` 의 `// 코드` · `// 발급 시각`.

전부 바로 아래 줄을 한국어로 다시 읽어준 것뿐이라, 지워도 잃는 정보가 없습니다. 오히려 이런 주석이 깔려 있으면 코드가 바뀌었을 때 같이 안 바뀌어서 거짓말이 되기 쉽습니다 (아래가 정확히 그 사례입니다).

## 남긴 것 (코드에 없는 이유를 적은 주석)

- `catch (e: IOException)` 안의 **"실패해도 캐시를 비우지 않는다"** — 여기서 아무것도 안 하는 게 실수가 아니라 의도라는 걸 알려줍니다. 이게 없으면 다음 사람이 "실패했는데 캐시 정리 안 하네?" 하고 `cache.remove()` 를 넣습니다.
- `clear()` 위의 **"로그아웃에서만 부른다"** — 호출부 제약이라 이 함수 본문만 봐서는 절대 알 수 없습니다.

## 확인 부탁드립니다: `// 24시간 캐시` 가 코드와 안 맞습니다

이 주석만 판단을 못 해서 **그대로 뒀습니다.**

```kotlin
// 24시간 캐시
if (cached != null && System.currentTimeMillis() - cached.issuedAt < 604_800_000L) {
```

`604_800_000L` 은 7일(7 × 24 × 60 × 60 × 1000)입니다. 24시간이면 `86_400_000L` 이어야 합니다. 둘 중 하나가 틀렸는데, 어느 쪽이 의도인지는 코드만 봐서는 알 수 없습니다.

- **정책이 24시간인데 상수가 틀린 경우** → 상수를 `86_400_000L` 로 고쳐야 합니다. 지금은 초대 코드가 만료된 뒤에도 6일 더 캐시에서 나갑니다.
- **정책이 7일인 경우** → 주석만 고치면 됩니다.

서버 쪽 초대 코드 만료 정책이 어느 쪽인지 알려주시면 맞춰서 정리하겠습니다. 제가 임의로 정하면 캐시 만료 동작이 바뀌는 거라 손대지 않았습니다.
