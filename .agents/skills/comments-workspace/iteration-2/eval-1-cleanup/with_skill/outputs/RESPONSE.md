주석 11개 중 9개를 지우고 2개를 남겼습니다. 기준은 "지우면 무엇을 모르게 되나"입니다.

## 지운 것 — 코드가 이미 말하고 있던 것

`// 초대 코드 저장소`, `// 캐시된 코드`, `// 캐시 확인`, `// API 호출`, `// 캐시에 저장`,
`// 코드 반환`, `// 캐시를 비운다`, `// 캐시 데이터 클래스`, `CachedCode` 의 `// 코드` ·
`// 발급 시각`.

전부 바로 아래 줄을 한국어로 옮겨 적은 것이라 정보가 0인데, 코드가 바뀌면 같이 안 바뀌어서
거짓말이 될 수는 있습니다. `// 코드가 null 이면 null 반환` 도 `response.code ?: return null`
와 글자 그대로 같은 말이라 뺐습니다.

## 남긴 것 — 코드가 담을 수 없는 것

- **`catch` 안의 한 줄** — 왜 실패 시 캐시를 안 비우는지. 안 고른 대안이라 코드에 존재하지
  않고, 없으면 다음 사람이 "실패했으니 비워야지" 하고 고쳐서 오프라인에서 코드를 못 쓰게
  만듭니다.
- **`clear()` 의 호출 규약** — 공개 함수가 호출부에 요구하는 것이라 `//` 대신 KDoc 으로
  올렸습니다. 구현(`cache.clear()`)을 아무리 읽어도 "로그아웃에서만"은 안 나옵니다.

## 주석 대신 코드로 민 것 하나

`// 24시간 캐시` 는 지우지도 남기지도 않고 상수로 옮겼습니다.

```kotlin
private companion object {
    const val CACHE_TTL_MILLIS = 7L * 24 * 60 * 60 * 1000
}
```

이제 기간이 이름과 식에 박혀 있어 주석이 따로 필요 없습니다.

## 확인 부탁드릴 것 하나

**주석과 코드가 서로 다른 말을 하고 있었습니다.** 주석은 24시간인데 `604_800_000L` 은
7일(7 × 24 × 60 × 60 × 1000)입니다. 어느 쪽이 의도인지는 이 파일만 봐서는 알 수 없어서
**동작을 바꾸지 않고 현재 값(7일)을 그대로 상수로 옮겼습니다.**

24시간이 맞다면 `1L * 24 * 60 * 60 * 1000` 으로 바꿔야 하고, 이건 주석 정리가 아니라 버그
수정이라 확인 후에 진행하겠습니다.

## 참고 (건드리지 않음)

`catch (e: IOException) { throw e }` 는 다시 던지기만 해서 실질적으로 하는 일이 없고, 지금은
위의 주석을 붙여 둘 자리 역할만 합니다. 요청 범위(주석 정리)를 벗어나서 그대로 뒀습니다.
정리하시려면 `try/catch` 를 없애고 그 주석을 `get()` 의 KDoc 으로 올리는 쪽이 맞습니다.
