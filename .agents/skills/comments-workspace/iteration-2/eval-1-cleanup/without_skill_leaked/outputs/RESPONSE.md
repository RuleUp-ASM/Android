주석 13개 중 11개를 지우고 2개를 남겼습니다. 세는 기준이 아니라 **"이 주석을 지우면 무엇을 모르게 되나"**로 하나씩 판정했습니다.

## 지운 것 — 코드가 이미 말하고 있음

`// 초대 코드 저장소`(클래스명), `// 캐시된 코드`, `// 초대 코드를 가져온다`, `// 캐시 확인`, `// API 호출`, `// 코드가 null 이면 null 반환`, `// 캐시에 저장`, `// 코드 반환`, `// 캐시를 비운다`, `// 캐시 데이터 클래스`, `// 코드` / `// 발급 시각`.

전부 바로 아래 코드를 한국어로 옮겨 적은 것입니다. 정보를 더하지 않으면서, 코드가 바뀔 때 같이 안 바뀌어 거짓말이 될 수는 있습니다. 실제로 아래 ⚠️ 한 건이 이미 그렇게 됐습니다.

## 남긴 것 — 코드가 구조적으로 담을 수 없음

1. **`// 실패해도 캐시를 비우지 않는다 — 비우면 비행기 모드에서...`**
   *안 고른 대안*입니다. "에러 났으니 캐시 비워야지" 하고 되돌리는 걸 막아줍니다. 안 고른 선택지는 코드에 존재하지 않으니 코드가 못 말합니다. 문장만 조금 줄였습니다.

2. **`clear()` 위 주석 → KDoc 으로 승격**
   호출부가 지켜야 할 계약("로그아웃에서만")이라 구현을 읽어선 안 나옵니다. `//` 대신 `/** */` 로 올려서 호출부에서 IDE 툴팁으로 보이게 했습니다. 앞에 붙어 있던 `// 캐시를 비운다`는 지웠습니다.

## 주석 대신 코드로 민 것

`604_800_000L` → `CACHE_TTL_MILLIS = 7L * 24 * 60 * 60 * 1000`

값의 의미는 주석이 아니라 이름이 맡는 게 맞습니다. 상수 이름과 계산식이 기간을 직접 말하므로 옆에 설명을 붙일 필요가 없어졌습니다. **동작은 그대로입니다.**

## ⚠️ 확인 부탁드립니다 — 주석과 코드가 어긋납니다

`// 24시간 캐시` 라고 적혀 있는데 실제 값 `604_800_000` 은 **7일**입니다. 24시간이면 `86_400_000` 이어야 합니다.

주석이 틀린 건지, 코드가 틀린 건지 제가 판단할 수 없어서 **현재 동작(7일)을 유지**했습니다. 원래 의도가 24시간이었다면 이건 주석 문제가 아니라 캐시 만료 버그이고, 초대 코드가 서버에서 만료된 뒤에도 6일 동안 옛날 코드가 나갈 수 있습니다. 어느 쪽이 맞는지 알려주시면 상수 값을 맞추겠습니다.

## 손대지 않은 것

`catch (e: IOException) { throw e }` 는 그대로 뒀습니다. 다시 던지기만 하므로 지워도 동작은 같지만, 그러면 위 1번 주석이 붙을 자리가 없어집니다. "여기서 캐시를 비우지 않는다"를 명시적으로 박아두는 자리로 보여서 요청 범위(주석 정리) 밖이라 판단했습니다. 정리를 원하시면 `catch` 를 걷어내고 주석을 `api.getInviteCode(...)` 호출 위로 올리겠습니다.

> 참고: `IOException` import 가 원래부터 빠져 있습니다. 이 파일만 떼어 보면 컴파일되지 않는데, 제 변경과는 무관합니다.
