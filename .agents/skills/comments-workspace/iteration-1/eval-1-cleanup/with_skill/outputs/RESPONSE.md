주석을 세어서 줄인 게 아니라, **지웠을 때 모르게 되는 게 있는지**로 하나씩 판정했습니다. 결과적으로 남은 주석은 0개인데, 지운 사실 중 하나는 코드로 옮겼습니다.

## 지운 것 — 코드를 한국어로 옮겨 적은 주석

`// 초대 코드 저장소`(클래스명), `// 캐시된 코드`, `// 초대 코드를 가져온다`, `// 캐시 확인`, `// API 호출`, `// 캐시에 저장`, `// 코드 반환`, `// 캐시를 비운다`, `// 코드`, `// 발급 시각` — 전부 바로 아래 줄이 이미 말하고 있습니다. 정보는 0인데 코드가 바뀌면 같이 안 바뀌어서 거짓말이 될 수 있는 쪽이라 지웠습니다.

## 코드로 밀어 넣은 것

한 줄은 정보가 있었습니다:

```kotlin
// 캐시가 있고 만료되지 않았으면 캐시를 반환
if (cached != null && System.currentTimeMillis() - cached.issuedAt < 604_800_000L) {
```

`604_800_000L` 이 "7일"이라는 건 코드가 말해 주지 않아서 주석이 대신 메우고 있었는데, 이건 주석이 아니라 이름의 자리입니다.

```kotlin
val isExpired: Boolean
    get() = System.currentTimeMillis() - issuedAt >= CACHE_TTL_MILLIS

private companion object {
    val CACHE_TTL_MILLIS = 7.days.inWholeMilliseconds
}
```

만료 판정이 `CachedCode` 안으로 들어가서 조건이 `!cached.isExpired` 로 읽히고, 기간은 `7.days` 로 눈에 보입니다. 주석이 없어도 같은 사실이 남습니다.

## 하나 확인 부탁드립니다

정작 코드가 못 말하는 건 **왜 하필 7일인가**입니다. 서버 초대 코드 만료 기간을 따라간 값이면 그건 이 파일 밖에 있는 계약이라 한 줄 남길 값어치가 있습니다 (예: `// 서버 초대 코드 만료와 같은 7일 — 더 길게 잡으면 죽은 코드를 공유하게 된다`). 근거를 모르는 채로 지어내면 나중에 더 헷갈리므로 지금은 비워 뒀습니다. 출처를 알려주시면 그 한 줄만 추가하겠습니다.
