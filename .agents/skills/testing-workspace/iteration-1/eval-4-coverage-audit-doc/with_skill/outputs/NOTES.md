# NOTES

## 구멍을 어떻게 찾았나

1. **`.claude/skills/testing/SKILL.md` → `references/strategy-doc.md`** 를 먼저 읽고 문서 형식·갱신 규칙을 확정했다. UI/ViewModel/인수 층의 "아직 없음" 사실 확인을 위해 `references/viewmodel.md`·`ui.md`·`acceptance.md` 도장 부분만 읽었다.
2. **`scripts/coverage_map.py`** 를 레포 루트에서 돌려 층×모듈 격자(270 `@Test`)와 "테스트 없는 대상" 60건을 얻었다. 2절 표는 이 출력을 손대지 않고 그대로 붙였다.
3. **스크립트를 읽고 그 사각지대를 손으로 메웠다.** 분류 로직이 이름 규칙(`*UseCase`/`*ViewModel`/`*RepositoryImpl`/`*Screen`)과 `entity/`·`model/` 안의 `require`/`init` 만 보므로, 다음은 60건 목록에 **나오지 않는다**:
   - `:core:network`(`TokenAuthenticator`, `NO_AUTH_PATHS`) — 이름 규칙에 안 걸린다
   - DTO → entity 매퍼 (`dto/` 안의 확장 함수) — 케이스 층 대상인데 규칙 밖이다
   - 테스트가 아예 없는 모듈 8개 — 격자에 **행 자체가 없어** 눈에 안 띈다
4. **각 후보를 실제로 열어 확인했다.** `Challenge.kt`·`GeofenceTarget.kt`·`SubmitDeviceIntroUseCase.kt` 는 원문을 읽었고, `challenge/data` 는 `?:` 기본값(40여 개)과 `ApiException.code` 분기(15종)를 grep 으로 셌다. 2.1 표의 근거는 전부 이 확인에서 나왔다 — 파일 크기만 보고 쓴 항목은 없다.
5. **CI 를 대조했다.** `.github/workflows/test.yml` 이 `./gradlew test` 만 돌린다는 사실과 `app/src/androidTest` 에 8건이 있다는 사실을 맞춰 보고, "테스트는 있는데 CI 가 안 돌린다"를 별도 구멍으로 분리했다. 격자의 `:app` 통합 18 을 액면대로 읽으면 놓치는 지점이다.
6. **4절 스토리는 `AppRouteRegistry.kt` 의 실제 등록 라우트에서만 뽑았다.** 없는 기능은 적지 않았다.
7. Gradle 은 지시대로 돌리지 않았다. 커버리지 숫자는 정적 카운트이므로 실행 없이도 정확하고, "테스트가 통과하는가"는 이 문서의 주장이 아니다.

## 판단: 넣은 것 / 뺀 것

- **60건을 그대로 붙이지 않았다.** `strategy-doc.md` 가 "전부 옮기면 3절이 60줄짜리 할 일 목록이 되어 아무도 안 본다"고 못 박는다. 대신 재생성 명령(`--gaps`)을 적어 원본을 잃지 않게 했다.
- **`메울 것`을 3절이 아니라 2.1 로 뺐다.** 스킬은 "안 메울 것만 3절"이라 하는데, 사용자의 요청은 "어디가 비어 있는지"라 메울 것도 문서에 남아야 했다. 3절(=미룬다)과 2.1(=곧 한다)을 섞으면 3절이 할 일 목록이 되어 위 규칙을 어긴다. 원래는 이 분류를 **사용자와 함께** 하라고 되어 있으나(감사 요청이라 대화 없이 진행), 아래 기준으로 갈랐다: **인프라 공사가 필요하면 3절, 오늘 파일 하나 열어 쓸 수 있으면 2.1.**
- **2.1 을 8줄로 잘랐다.** 순서는 "못 잡으면 사용자에게 보이는가 × 지금 쓸 수 있는가"다. `MyChallengeStoreImpl`·`TargetAppStoreImpl` 같은 얇은 위임체나 `:home:presentation` 같은 화면 전용 모듈은 뺐다 — 전자는 잡을 규칙이 없고, 후자는 UI 인프라에 묶여 3절 소관이다.
- **3절을 6줄로 묶었다.** ViewModel 24개·화면 30개를 한 줄씩 쓰면 54줄이 되는데, 막고 있는 원인이 **각각 하나**(coroutines-test + NavigationHelper Fake / Robolectric)라 그 단위로 묶는 게 정직하다. "풀리는 조건" 칸에 그 한 건을 적었다.
- **DI·디자인시스템은 "구멍"이 아니라 "안 한다"로 적었다.** SKILL.md 가 명시적으로 테스트 대상에서 뺀 것들인데, 커버리지 0 이라는 이유로 구멍 목록에 올리면 문서가 스스로의 기준과 싸운다. 다만 릴리스 sink 배제처럼 바인딩이 정책이 되는 예외는 같은 줄에 남겼다.
- **숫자를 보정하지 않고 각주로 남겼다.** 표는 스크립트가 재생성하므로 손으로 고치면 다음 갱신에 사라진다. androidTest 8건·템플릿 2건·행 없는 모듈 8개는 "표를 그대로 믿기 전에" 각주로 뺐다.
- **4절 상태를 전부 `미구축`으로 적었다.** 인수 층이 0 이므로 그 외의 값을 쓰면 거짓이다. 대신 각 스토리의 **구멍**을 명시해 4절이 2.1·3절의 우선순위 근거가 되게 했다.
- **`VERIFICATION_TEST_PLAN.md` 는 손대지 않고 링크로만 가리켰다** (성격이 다른 수동 QA 문서).
- **`ExampleUnitTest` 삭제를 제안만 하고 실행하지 않았다.** 이번 작업은 감사·문서화 범위이고, 레포 파일은 하나도 고치지 않았다.
