# 주석 달기

주석은 적을수록 좋다. 하지만 목표는 "주석 0"이 아니라 **읽는 사람이 코드만 보고도 행동을
이해하는 것**이다. 주석을 지워서 이해가 막히면 그건 개선이 아니다.

## 기준선 하나

**코드에 있는 것은 코드가 말하게 하고, 코드에 없는 것만 주석이 맡는다.**

코드는 "무엇을 하는가"를 이미 담고 있다. 그걸 한국어로 옮겨 적는 주석은 정보를 더하지 않고,
코드가 바뀔 때 같이 안 바뀌어서 거짓말이 된다.

반면 코드가 **구조적으로 담을 수 없는 것**이 있다:

- **고르지 않은 대안** — 안 고른 선택지는 코드에 존재하지 않는다. 왜 그게 아닌지는 코드가 못 말한다.
- **바깥에 있는 계약** — 서버 명세, OS 동작, 정책 문서. 이 파일 안에 근거가 없다.
- **깨졌을 때 일어나는 일** — 이 줄을 고치면 어디가 어떻게 망가지는지는 여기서 안 보인다.

이 셋이 주석의 자리다. 나머지는 코드로 밀어 넣는다.

## 주석을 쓰고 싶어지면 — 먼저 코드를 고친다

주석을 달고 싶다는 충동은 **코드가 덜 말하고 있다는 신호**다. 바로 적지 말고 무엇이 안 보이는지
짚어서, 그걸 코드로 옮길 수 있는지 먼저 본다.

| 안 보이는 것 | 주석 말고 이걸 | 예 |
|---|---|---|
| 값의 의미 | 이름 · value class · enum | `RoutineDescription.of()` 가 길이 규칙을 가둔다 |
| 분기 조건의 뜻 | 이름 붙인 파생 프로퍼티 | `excludesLowSample`, `isFailure`, `hasMetrics` |
| 단계의 구분 | 함수 추출 | `// 1) 수집` 대신 `capture()` |
| 매개변수의 정체 | named argument · 전용 타입 | `send(force = true)` |
| **왜 그렇게 했는가** | **주석** | 코드로 못 담는다 |

### 예

```kotlin
// before — 주석이 코드의 부족분을 메우고 있다
val rate: Double?  // 표본 미달이면 null. 0 이 아니다

// after — 구분이 타입에 박혀서 잘못 쓸 수가 없다
sealed interface SuccessRate {
    data object NoSample : SuccessRate
    data class Of(val value: Double) : SuccessRate
}
```

```kotlin
// before
// 완료율·성공비 정렬은 표본 미달 방이 빠진다
if (sort == COMPLETION_RATE || sort == SUCCESS_FAIL_RATIO) { ... }

// after — 조건에 이름이 붙어 화면마다 복제되지 않는다
if (sort.excludesLowSample) { ... }
```

### 어디까지 코드로 밀 것인가

타입을 늘리는 데도 비용이 든다. 기준은 **그 구분을 틀렸을 때 무슨 일이 나는가** 하나다.

- `roomSuccessRate` 의 null 을 0 으로 접으면 **갓 만든 방이 실패한 방으로 그려진다** → 타입으로 가둔다.
- `imageUrl` 이 null 이면 안 그리면 그만이다 → 타입을 늘리지 않는다. 필요하면 주석 한 줄.

틀려도 화면 표기가 빠지는 정도면 주석으로 충분하고, 잘못된 사실이 사용자에게 보이거나 판정에
섞이면 타입으로 막는다.

**그래도 안 되면 주석을 단다.** 코드로 밀 수 없는데 억지로 미는 게 더 나쁘다 — 이름이 길어지고
타입이 늘어서, 정작 읽는 사람은 더 헤맨다.

## 그래서 남는 주석

### 먼저 — 짧게 쓴다

안 읽히는 주석은 없는 것과 같다. "왜"를 남기라는 건 **설명을 늘어놓으라는 뜻이 아니다.**
길고 빽빽하면 다음 사람은 그 블록을 통째로 건너뛰고, 그 순간 주석을 단 값어치가 사라진다.

**한 줄이 기본, 두 줄이 상한이다.**

| 이러지 말고 | 이렇게 |
|---|---|
| 원리를 설명한다 | **증상으로 말한다** |
| 배경부터 깐다 | **결론을 앞에 둔다** |
| 아는 걸 다 적는다 | **읽는 사람이 모르는 것만 적는다** |

```kotlin
// 길어서 안 읽힌다
// Play Services 의 지오펜스 API 는 setNotificationResponsiveness 를 지정하지 않으면 내부적으로
// 기본값 0 을 사용하는데, 이 값은 전이 발생 시 가능한 한 빨리 콜백을 전달하라는 의미이며, 그 결과
// 시스템이 지오펜스 검사를 다른 위치 관련 작업과 배치 처리할 수 없게 되어 위치 하드웨어가 상시
// 활성 상태로 유지되고 배터리 소모가 증가한다.

// 이거면 된다
// 0(기본값)이면 배칭이 꺼져 위치 하드웨어가 상시 깨어 있다.
```

원리는 궁금하면 찾아볼 수 있다. **찾아볼 수 없는 건 "그래서 어떻게 되는데"** 뿐이고, 그게 짧다.

읽는 사람은 **이 코드를 처음 보고 고치려는 사람**이다. 그가 이미 아는 것(언어 문법, 흔한 라이브러리
동작)은 빼고, 그가 모른 채 손댔다가 깨뜨릴 것만 남긴다.

아래 다섯 갈래는 **무엇을 남기느냐**의 목록이지 분량 허가가 아니다. 어느 것이든 한 줄로 끝낸다.

### 줄일 수 없을 때는 옮긴다

가끔 진짜로 안 줄어드는 게 있다. 문단마다 **다른 질문**에 답하고 있어서 뭘 빼도 답 하나가 사라지는
경우다. 그건 잘 쓴 긴 주석이 아니라 **주석이 아닌 것이 주석 자리에 있는 것**이다 — 설계 결정은 왜 그
선택을 했는지·무엇과 견줬는지·무엇을 포기했는지로 이루어지고, 그건 이슈나 PR 이 담는 형식이다.

판별은 한 줄이다. **"이 문단들이 서로 다른 질문에 답하는가?"** 그렇다면 줄이지 말고 옮긴다.

```kotlin
// 옮기기 전 — 12줄 KDoc. ① 이 값이 뭔가 ② 늦게 배달돼도 판정이 왜 멀쩡한가
// ③ 왜 상수 하나로 못 박지 않았나. 셋 다 필요한 답이라 뭘 빼도 손해다.

// 옮긴 뒤
/** 통지 지연 허용치. 체류 목표가 기본값보다 짧으면 거기 맞춘다 — 근거는 #357. */
```

코드를 훑는 사람은 한 줄로 끝내고, 정말 궁금한 사람만 이슈를 연다. 게다가 이슈에는 **논의와 반대
의견까지** 남아 있어 주석보다 정보가 많고, 결정이 뒤집히면 이어 적으면 된다 — 주석처럼 조용히 낡지
않는다.

**링크할 곳이 없으면 옮기지 말고 먼저 이슈를 만든다.** 갈 곳 없이 지우면 근거가 증발한다.

### ① 안 고른 대안

가장 값어치 있는 주석이다. 나중에 "이거 그냥 이렇게 하면 되잖아" 하고 되돌리는 걸 막는다.

```kotlin
// 0m·"mock 아님"으로 접으면 없던 사실이 판정에 들어간다.
val accuracy = location?.accuracy
```

```kotlin
// 모르면 잠긴 것으로 본다 — 못 들어갈 방을 열려 있는 것처럼 보이게 하면 안 된다.
joinable = joinable ?: false
```

### ② 바깥에 있는 계약

이 파일을 아무리 읽어도 안 나오는 근거. **어디를 열어봐야 하는지**까지 적는다.

```kotlin
// base(.../api/) + v1/... → /api/v1/challenges/{id}/ranking
@GET("v1/challenges/{challengeId}/ranking")
```

```kotlin
/** 오늘 인증 결과(명세 GET verifications/today). 연속 일수와 이의 기한도 여기서 온다. */
```

```xml
<!-- 시스템이 BOOT_COMPLETED 를 보내므로 exported=true 여야 한다. -->
<receiver android:name=".BootReceiver" android:exported="true">
```

마지막 예가 전형이다. **위험해 보이는데 의도된 것**은 반드시 근거를 남긴다. 안 남기면 다음
사람이 "보안 문제네" 하고 고쳐서 기능을 깬다. 그래서 이건 값어치 대비 가장 짧은 주석이기도 하다 —
한 줄이면 충분하다.

### ③ 깨지면 무엇이 망가지는가

테스트 주석의 기본형이다. 결과를 되풀이하지 말고 **이 단언이 무너졌을 때의 증상**을 적는다.

```kotlin
@Test
fun `명세의 6종만 정의돼 있고 기본은 인기순이다`() {
    // 구 TEMPLATE_USAGE 가 남아 있으면 서버가 400 INVALID_SORT_TYPE 으로 막는다.
```

일반 코드에서도 같다 — `// 여기서 순서를 바꾸면 세션이 저장되기 전에 분기해 로그인 화면으로 튄다`.

### ④ 값이 비었을 때의 뜻

타입으로 가두지 않기로 한 nullable 은 **null 이 "0"인지 "모름"인지**를 남긴다. 이 둘은 다른
사실이고, 화면이 잘못 접으면 없던 일이 생긴다.

```kotlin
// 모르면 false — 못 바꾸는데 열어 두면 눌렀다 429 를 본다
val changeAvailable: Boolean = false,
```

### ⑤ 가정

명세가 비어서 한쪽을 골랐다면 **고른 사실과 무엇이 틀릴 수 있는지**를 남긴다. 침묵한 추측은
나중에 아무도 못 찾는다.

```kotlin
// 커서 페이징으로 가정한다. 서버가 page/size 면 이 필드가 바뀐다.
```

## 지우는 것

| 종류 | 왜 |
|---|---|
| 코드 되풀이 | `// 사용자 저장` 위의 `saveUser()`. 정보가 0인데 낡을 수는 있다 |
| 주석 처리된 코드 | git 이 한다. 남겨두면 살아 있는 코드인지 아무도 모른다 |
| 낡아서 틀린 주석 | **지우지 말고 고친다.** 그 자리에 사실이 필요했으니 누가 적은 것이다 |
| 맥락 없는 TODO | 누가 언제 무엇을 하는지 없으면 영원히 남는다. 이슈로 올리고 번호를 적는다 |
| 구분선 남발 | 파일이 길어서 필요하면 두되(`// ---------- 탐색 ----------`), 파일을 쪼갤 때가 아닌지 먼저 본다 |

낡은 주석을 만나면 **지우기 전에 그 주석이 담은 사실이 지금 코드 어디에 있는지 확인한다.**
코드로 옮겨졌으면 지우고, 아직 코드 밖에 있으면 현재 사실로 고쳐 남긴다.

## 형식

- **KDoc(`/** */`)** — 타입과 공개 함수의 계약. 첫 줄에 한 줄 요약과 근거(명세 경로·정책 이름).
  호출부가 지켜야 할 것(재시도 금지·키 재사용·선행 조회)이 있으면 여기 적는다. 구현을 읽어선 안 나온다.
- **`//`** — 그 줄이나 블록에만 걸리는 판단. 대상 **바로 위**에 둔다.
- **줄 끝 주석** — 짧은 값 힌트에만(`val ratio: Double, // 0~1`). 문장이 되면 위로 올린다.
- 한국어로 쓴다. 코드 식별자는 그대로 두고 번역하지 않는다.

## 남의 주석을 판정할 때

리뷰나 감사에서는 주석 하나하나에 같은 질문을 던진다:

1. **이 주석을 지우면 무엇을 모르게 되나?** — 답이 "없다"면 지운다.
2. **모르게 되는 그것이 코드로 표현 가능한가?** — 가능하면 코드 수정을 제안한다. 주석 유지는 차선이다.
3. **지금도 사실인가?** — 코드와 어긋나면 **주석이 아니라 어느 쪽이 틀렸는지**를 먼저 가린다.
   주석이 옳고 코드가 틀렸을 수 있다. 그게 버그를 찾는 흔한 경로다.

지적은 "주석이 많다"가 아니라 **어느 주석이 왜 값어치가 없는지**로 한다. 세는 것은 기준이 아니다.

## 마무리

작업을 마치면 새로 쓴 주석을 다시 훑고 스스로 묻는다 — **이 문장이 코드에 이미 있는가?**
있으면 지우고, 없으면 그게 왜 코드에 없는지가 주석의 존재 이유다. 답이 안 나오면 그 주석은
아직 덜 쓰인 것이다.
