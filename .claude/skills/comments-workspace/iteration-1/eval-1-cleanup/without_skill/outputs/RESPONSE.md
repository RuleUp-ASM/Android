# 사용자에게 할 말

주석을 세서 줄인 게 아니라, **하나씩 "이걸 지우면 뭘 모르게 되나"** 를 물어서 정리했습니다.
답이 "없다" 인 것만 지웠고, 지우면 안 보이게 되는 건 주석 대신 코드로 옮겼습니다.

## 지운 것 — 코드를 한국어로 옮겨 적은 주석

`// 초대 코드 저장소`(클래스명 그대로), `// 캐시된 코드`, `// 초대 코드를 가져온다`,
`// API 호출`, `// 캐시에 저장`, `// 코드 반환`, `// 캐시를 비운다`, `// 코드` / `// 발급 시각`.
전부 바로 아래 줄이 이미 말하고 있는 내용이라 정보가 0인데, 코드가 바뀌면 같이 안 바뀌어서
거짓말이 될 수는 있는 주석들입니다.

## 주석 대신 코드로 옮긴 것

`// 캐시가 있고 만료되지 않았으면 캐시를 반환` 은 유일하게 정보가 있는 주석이었습니다.
`604_800_000L` 이 뭔지 코드가 못 말하고 있었기 때문입니다. 그래서 주석을 다듬는 대신

- 상수에 이름을 붙이고 (`CACHE_TTL_MILLIS = 7L * 24 * 60 * 60 * 1000`)
- 조건에 이름을 붙였습니다 (`cached.isExpired()`)

이제 조건 자체가 "만료 안 됐으면 캐시" 라고 읽혀서 설명할 게 남지 않습니다.
같은 이유로 `// 코드가 null 이면 null 반환` 도 지웠습니다 — 엘비스 연산자가 그대로 말합니다.

## 확인 부탁드릴 것 하나

**7일 TTL 의 근거를 모르겠습니다.** 서버 초대 코드 만료와 맞춘 값이라면 그건 이 파일을
아무리 읽어도 안 나오는 바깥 계약이라 한 줄 남길 값어치가 있습니다. 예를 들면

```kotlin
// 서버 초대 코드 만료(7일)와 맞춘 값 — 더 길면 죽은 코드를 내주게 된다.
```

근거를 모른 채 추측으로 적을 수는 없어서 지금은 이름만 붙여 뒀습니다.
출처를 알려주시면 그 한 줄만 추가하겠습니다.

`response.code` 가 null 인 경우도 마찬가지입니다 — "아직 발급 전" 인지 "발급 불가" 인지에
따라 남길 말이 달라지는데, 명세를 확인하지 않은 상태라 손대지 않았습니다.
