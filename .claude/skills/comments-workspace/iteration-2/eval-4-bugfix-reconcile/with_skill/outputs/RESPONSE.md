`reconcilePlan` 이 requestId 만 비교하고 있어서, 앵커를 옮겨도 "이미 등록됨"으로 판정돼
`toAdd` 에서 빠졌습니다. OS 에는 옛 좌표의 펜스가 그대로 남아 있으니 옛 자리에서 계속 터진 거고요.

## 고친 것

- 비교 대상을 id 집합에서 **직전 등록 목표 전체**로 바꿨습니다: `registeredIds: Set<String>` → `registered: List<GeofenceTarget>`.
- `toAdd` 는 이제 `registeredById[it.requestId] != it` 로 뽑습니다. 미등록(=null)과 좌표·반경·체류 변경이 한 조건으로 잡힙니다.
  `GeofenceTarget` 이 data class 라 비교는 값 전체로 이뤄집니다.
- `toRemoveIds` 는 그대로 — 목표에서 사라진 id 만 제거합니다.

재등록 자체는 별도 remove 가 필요 없습니다. `addGeofences` 가 같은 requestId 를 멱등 교체하므로,
같은 id 로 새 좌표를 다시 넣으면 옛 펜스가 덮어써집니다.

## 호출부에서 해야 할 일

**직전 등록분을 id 만이 아니라 좌표까지 로컬에 보존해야 합니다.** OS 는 등록된 펜스 목록을
되돌려주지 않으므로, 이 함수가 이동을 감지할 근거는 로컬 보존분밖에 없습니다.
id 만 저장하는 저장소를 쓰고 있다면 스키마를 목표 전체로 넓혀 주세요.

## 안 고른 방법

requestId 에 좌표 해시를 섞어 "좌표가 바뀌면 id 도 바뀌게" 하는 방법도 있지만 택하지 않았습니다.
이 값은 GEOFENCE 이벤트의 anchorId 로 서버에 보고되는 멤버 자연키 파생값이라, 앱이 마음대로
바꾸면 서버 판정이 어긋납니다. 코드에도 그 이유를 한 줄 남겨 뒀습니다.
