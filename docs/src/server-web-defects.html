RuleUp 서버·웹 전달 결함

2026-09-14 수동 QA 2회차에서 나온 것 중 Android 레포에서 고칠 수 없는 항목(13건) · 스테이징 기준

이 문서의 범위. 앱 쪽 결함은 #454~#459 로 고쳐 PR 을 올렸다. 여기 모은 것은 원인이 서버 응답·웹 배포·데이터에 있어 앱을 고쳐도 사라지지 않는 항목이다. 각 항목에 재현 근거(요청·응답)와 기대 동작을 적었다.

우선순위. 높음 실사용자가 기능을 못 쓴다 · 중간 잘못된 사실이 화면에 보인다 · 낮음 계약·데이터 정리.

웹 배포

높음운영 assetlinks.json 이 템플릿 그대로다 웹 · QA NAV-01

근거
https://android.ruleup.co.kr/.well-known/assetlinks.json 응답이 "package_name": "REPLACE_ME_패키지명", "sha256_cert_fingerprints": ["REPLACE_ME_DEBUG_SHA256_지문", "REPLACE_ME_RELEASE_SHA256_지문"]. 에뮬레이터에서 도메인 검증 상태 1024(미검증)
영향
설치된 앱이 친구·챌린지·감시자 초대 링크를 받지 못하고 브라우저로 열린다
기대
com.ruleup.android_ruleup 과 업로드·Play 앱 서명 키의 SHA-256 지문으로 채워 배포

높음/w · /c 초대 경로의 웹 페이지가 404 다 웹 · QA NAV-05

근거
/inv/{code} 는 /invite 랜딩으로 가지만 /w/{token}·/c 는 "HTTP ERROR 404"
영향
앱 미설치(또는 링크 미검증) 사용자가 감시자·챌린지 초대를 열면 빈 오류 페이지를 본다
기대
설치 유도 랜딩(스토어 이동) 제공

서버 API

높음문의·이의 첨부 사진 업로드가 500 이다 서버 · appeals/support · QA CS-07

근거
POST /v1/appeals/images multipart image(image/jpeg, 405×900 PNG 를 JPEG 로 변환) → 500 {"code":"INTERNAL_SERVER_ERROR","message":"서버 내부 오류가 발생했습니다."} (2026-09-15 00:35, 앱 이미지 리더 수정 #460 적용 빌드)
영향
문의 첨부·이의 증빙 사진을 올릴 수 없다
기대
명세대로 200 {"imageUrl": "/files/…"}. 문의 접수 명세는 "업로드 API 가 준 /files 주소"라고만 적혀 있어 문의 전용 업로드 경로가 따로 필요한지도 확인 필요

높음앱 표준 sync 페이로드를 400 INVALID_SIGNAL_PAYLOAD 로 거부한다 서버 · verification

근거
POST /v1/verifications/sync 본문 {"activeChallengeIds":[], "signals":[{"type":"WAKE","firstScreenOn":1789336414750,"deviceSecure":false}], "permissions":{…}, "diagnostics":{…}, "gaps":[]} → 400 {"code":"INVALID_SIGNAL_PAYLOAD","message":"인증 신호 페이로드가 올바르지 않습니다."}. 23:26 콜드스타트에서도 같은 400 재현
영향
앱은 해당 배치를 버린다(재전송 없음) — 이 조건의 신호가 판정에 반영되지 않는다
기대
어느 필드가 틀렸는지 reason 으로 알려 주거나, 활성 챌린지가 없을 때의 WAKE 신호를 무시하고 200

중간챌린지 신고(CHALLENGE_MASKED) 뒤에도 제목·이미지가 가려지지 않는다 서버 · report/challenge · QA REP-06

근거
POST /v1/reports → {"blocked":true,"hiddenEffect":"CHALLENGE_MASKED"} 이후에도 GET /v1/challenges?filter=…·상세 응답의 title 이 원문(「단어 암기하기」). 차단 목록에서만 "숨김 처리된 챌린지"
기대
신고자 기준으로 목록·상세·진행률 응답의 title·imageUrl 마스킹(앱은 신고 뒤 재조회하도록 #464 에서 수정)

중간마이 홈 카운트와 챌린지 목록이 어긋난다 서버 · mypage · QA MY-01

근거
GET /v1/me/home counts.inProgress=4 · completed=0 인데 GET /v1/challenges?filter=IN_PROGRESS 는 0건, 네 챌린지 모두 status=COMPLETED
기대
counts 를 목록 filter 와 같은 기준으로 집계

중간진행률 조회가 status 필터를 무시한다 서버 · verification · QA MY-01

근거
GET /v1/verifications/progress?status=ACTIVE 응답에 status=COMPLETED 챌린지 4건
영향
홈이 끝난 방을 "진행 중 · 오늘 시작"으로 그렸다(앱에서 COMPLETED 제외로 #461 수정)
기대
status 쿼리대로 거르기

중간오늘 인증 응답에 verificationId 가 없어 수동 인증 해제가 막힌다 서버 · verification · QA MAN-09 · #451

근거
체크 직후에는 해제되지만 화면 재진입 뒤 GET /challenges/{id}/verifications/today 에 verificationId 가 없어 해제 요청을 만들 수 없다
기대
체크된 날은 verificationId 포함. 관련: #453(상세 MANUAL 인데 제출이 NOT_MANUAL_CHALLENGE)

낮음대상 앱 미설정을 4xx 로 내린다 서버 · challenge

근거
GET /challenges/{id}/my-screen-apps → 400 SCREENTIME_NOT_CONFIGURED("측정할 앱이 아직 설정되지 않았어요")
기대
정상 상태이므로 200 {"apps":[]}. 4xx 는 로그·모니터링에 오류로 쌓인다

낮음탐색 빈 결과에 emptyReason 이 없다 서버 · explore · QA JOIN-03

근거
